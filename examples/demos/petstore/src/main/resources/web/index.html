How does SPP describe this business?

Calculation and shared checks

atomic calculate priceLine(OrderLine) {
    OrderLine.amount = roundHalfUp(
        OrderLine.unitPrice * OrderLine.quantity,
        2
    );
}

Participants define the facts a service needs. PHY selects the concrete numeric representation; business code does not need to write BigDecimal method calls.

Explicit business transactions

Contract ReturnRequestAgreement {
    Buyer;
    ShopOrder;
    String reason;
    Receipt;
}

Scenario serial requestShopReturn(
    Buyer,
    ShopOrder,
    ReturnRequestAgreement
) {
    checkReturnRequestAgreementInput;
    initializeReturnRequestAgreement;
    findBuyer;
    identify(Buyer);
    findShopOrder;
    identify(ShopOrder);
    checkOrderOwner;
    checkReturnRequest;
    prepareReturnRequest;
    prepareReturnRequestReceipt;
    transaction {
        updateShopOrder;
        insertReceipt(ReturnRequestAgreement.Receipt);
    }
}

Contract fields and scenario entries can omit instance names and use participant type names directly. Parameterless calls bind by unique type. Each business scenario declares its own transaction boundary; APP selects service realization and PHY supplies the commit guarantees.

This is a local, single-database demonstration. Its wallet is not connected to a real payment provider. Ordinary updates use conditional saves based on queried revisions, while the quantum domain protects balances and inventory. Parallel queries demonstrate reading behavior; refreshing this page does not produce a transaction snapshot.
